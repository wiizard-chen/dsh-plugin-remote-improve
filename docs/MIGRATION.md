# 迁移记录

日期：2026-10-28。

## 已迁入的基线

- 三个已在本机 Web profile 使用的通用插件，按文件白名单迁移。
- 各包的运行时 JS 和 bundle patch 保持原逻辑；manifest 的包名、入口和接口声明保留，仅将性能包描述改为实验性措辞；复制按钮的测试路径改成虚构目录。
- 原来的两个独立性能安装器统一由根目录安装脚本替代，不保留错误的加载顺序提示或机器特定操作说明。
- 原 README 全部重写，避免把真实项目、会话标题、部署信息或测试记录发布出去。
- 新增隔离安装测试、合成宿主挂接测试和结构检查；没有复制实际用户会话作为 fixture。

## 本机接入方式

本机 Web profile 中，三个通用插件的 `link:` 依赖及对应模块软链接改为指向此 checkout 的 `packages/`；其他依赖和配置保留。源码只有这一份受到 Git 管理，不复制真实 profile 进仓库。三个旧源目录改为指向新源码的兼容软链接，避免继续编辑到独立旧副本；原文件另存在仓库外的本机私有迁移备份中。

安装器会把变更前的 manifest 和链接状态保存在 profile 下，备份不进入本仓库。安装不是服务重启；正在运行的 Web 进程可能仍持有之前加载的同一逻辑。需要加载将来的代码修改时，请等任务结束，再按原启动方式重启服务并刷新浏览器。

## 已知后续事项

此次只迁移与补充工程化支撑，不改变原有性能算法：

1. 预算目前统计 JSON 字符串长度，不是严格 UTF-8 字节数。
2. 上下文补全按整页追加，软/硬预算和轮次数是停止条件，不是严格最终上限。
3. DSH 安装定位失败可能抛错；内部接口变化虽有部分跳过保护，不等于所有错误均可无害忽略。
4. WebSocket 压缩修改共享 prototype，有进程级作用域。

因此性能插件必须显式选择安装；与当前 DSH 版本之外的兼容性需要实际验证。这些缺陷应作为后续独立改动，有测试后再修改，不混入迁移提交。
